# Output guidance

Keep each project in its own folder, with its main artifact easy to open. Choose a useful grouping when needed; the existing categories are examples, not limits on media.

Do not put temporary render frames, dependency caches, or unrelated scratch files here. Preserve a prior approved version when revising an artifact.

## Organization

Use a meaningful project name and keep related assets together with relative paths intact. Preserve editable source and reproduction instructions, including dependency metadata when applicable. Keep generated exports and optional review evidence distinguishable from source.

Include concise project notes covering intent, meaningful decisions, asset provenance, actual checks, and limitations. These can share one document; no separate brief or QA template is required. Preserve prior approved versions and add completed work to the local outputs index.

Deliver the formats appropriate to the request. For time-based work, distinguish file or frame checks from normal-speed playback review. For interactive work, distinguish screenshots from exercised behavior. Include an archive only when useful or requested, and verify it before delivery. Structural checks do not establish artistic quality.
