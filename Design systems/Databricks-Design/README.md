# Databricks Design

Use only for a Databricks brief. Load the brand profile, then the method needed for the task.

| Resource | Use |
| --- | --- |
| [design.md](design.md) | Palette, typography, identity rules and unresolved brand gaps |
| [Product visual references](product-visual-references.md) | Optional provisional composition profile; select `product-visual-references.md` or `databricks-product-screenshots` for this aesthetic |
| [Product visual references review](product-visual-references-eval.md) | Lightweight A/B iteration, truth and identity gates, copyable review template, and hypothetical cases; load when evaluating screenshot assets |
| [Muller-Brockmann Grid Design](../../skills/muller-brockmann-grid-design/SKILL.md) | Content-led grids, typography, alignment and hierarchy |

Supply audience, message, content/data, dimensions, fidelity and approved assets/template. Established brand and product rules take precedence over proposed defaults. Keep authentic product UI distinct from marketing framing.

For the screenshot profile, select 1–3 relevant images and observations from the [annotated reference index](<../../examples/Product Visual References/README.md>). The 22 user-supplied Claude-inspired references inform presentation, not Databricks product identity or feature claims. This profile is inactive until selected and does not restyle authentic UI with corporate marketing tokens.

Example: “Use design.md and Muller-Brockmann Grid Design to create a five-slide Genie carousel at the supplied dimensions. Lead with the business finding, preserve brand identity, and inspect exports at feed size.”

Fonts, brand artwork and source media are not bundled. Load references only when relevant.
